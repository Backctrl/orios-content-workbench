# 公众号写作执行标准（融合 WeWrite 方法论）

> 本文档把 [imraywang/wewrite](https://github.com/imraywang/wewrite)（公众号内容全流程 Skill，v4.2.1）的
> 执行标准融合进 OriOS 内容工作台的公众号写作环节。wewrite 完整模块文档（选题/写作/审稿/改写/配图/排版/发布/风格/数据）
> 已复制到内容库 `_工作台/skills/wewrite*/`，CLI 在 `_工作台/wewrite-cli/`（`wewrite run/score/preview/hotspots` 等）。
> 本标准是 `approved_article` 闸门的写作与验收依据，与 `output-contract.md`、`topic-pipeline.md` 配合使用。

## 一、选题评估标准（选题库筛选）

候选选题进入选题库时按三维评分（各 1-10 分），综合分 = 热度 × 0.3 + 相关度 × 0.4 + 切入价值 × 0.3：

- **热度**：热搜前 10 → 8-10；10-30 → 5-7；之后 → 1-4；多平台同现 +2（封顶 10）。常青选题热度固定 5。
- **相关度**：直接命中账号选题方向 → 8-10；间接相关 → 5-7；勉强相关 → 3-4；无关 → 0。**命中黑名单（blacklist）→ 直接 0 淘汰。**
- **切入价值**：有反直觉点/信息差 → 8-10；有争议可讨论 → 6-7；纯资讯搬运 → 3-4；太浅或太复杂 → 1-2。按 content_style 加成（干货/故事/情绪/热点/测评各 +2，封顶 10）。

历史去重：核心关键词近 7 天已写 → -3 分并标注「⚠️ 近期已覆盖」；7-30 天 → -1 分；>30 天不扣。
高频需求角度选题：用**同题密度**顶替热度分（≥5 账号 8-10；3-4 账号 6-7；1-2 账号 3-5），并附「逻辑拆解」：
需求本质（情绪宣泄/信息差/身份认同/实操焦虑）+ 形式逻辑（标题公式/结构钩子，可复用）+ 供给缺口（深度不够/案例过时/人群错位）。
窗口内可跟进同角度；窗口过后必须差异化（对立观点/更深一层/换人群），给不出差异化的照抄式选题切入价值封顶 4 分。**模拟的是逻辑和结构，不是搬运内容。**

## 二、文章任务书（brief 选题卡扩展）

动笔前先明确（映射到 brief.md 选题卡字段，可补充字段、不可省略核心项）：

- **读者**（目标读者）：`who` 具体读者 + `context` 阅读情境 + `question` 读者真正要解决的问题（= brief 核心问题）
- **交付**（goal）：`takeaway` 读完能复述的一个结论 + `action` 读完可采取的行动（纯观点文可写判断方法；`action` 必须与题目相称，不为凑干货制造步骤）
- **核心判断**（thesis）：`statement` 全文核心判断 + `novelty` 相较常见说法新增了什么（找不到可靠新角度时，缩小问题/补适用条件/给更好用的判断框架，**不强行唱反调**）+ `boundary` 结论成立条件（= brief 边界）+ `counterpoint` 最强反方或替代解释（= brief 待验证问题）
- **个人材料**：只记录用户本次明确提供的经历/观察/原话；没有时不得写作者亲历事件、朋友、对话、时间地点和感官细节
- **章节**：每节推进什么、对应哪些主张

## 三、主张清单（claims.yaml）

每个主张：`id/text/type/source_ids/status/boundary`。

- `type`：fact / inference / opinion / user_experience
- `status`：supported / bounded / unsupported
- **fact 必须有能直接支持的来源**，否则删除或标 unsupported，不得进入正文
- **inference 要列出依据并明确这是推断；opinion 不伪装成共识**
- **user_experience 只能来自用户本次明确提供的材料**（来源账本标 user_provided）；范文、模型记忆、人格示例都不是用户经历
- 每一节至少服务一个主张；无法对应主张的段落默认删除

## 四、内容增强策略（按框架选一项）

- **观点/热点解读 → 可支持的新角度**：先看已有解释的共识、分歧和被忽略的条件，选一个有证据的新贡献（更准确的因果、更清楚的边界、对具体读者的影响、更好用的判断框架）；不能为「尖锐」反对主流，不能把推测写成内幕。
- **痛点/清单 → 行动可用性**：逐节检查读者能否开始行动，补齐步骤、条件、成本、风险和失败信号；具体工具、参数、价格、版本必须核实并注明时效；不能把泛泛建议包装成确定答案。
- **故事/复盘 → 有来源的真实细节**：只用用户明确提供或可靠来源记载的时间、地点、对话、细节；直接引语必须能逐字核对；材料不足时改用事实叙述或换框架，禁止「合理重建」、拼接人物、添加感官细节。
- **对比 → 决策条件**：先定义共同标准再比较；官方信息用于功能价格，用户评价只代表被引用者体验；无法验证的「隐藏坑」不写；输出「什么情况下选什么」，不是整齐但无结论的优缺点表。

通过检查：新角度能由证据和逻辑支持；具体信息都有来源或明确边界；没有把第三方故事/范文/模型记忆改写成作者亲历；每个增强点都服务读者问题，删掉后毫无影响的内容不加入。

## 五、编辑审稿（approved_article 闸门的验收依据）

五项各 1-5 分，**通过 = 平均分 ≥ 4、单项 ≥ 3、无阻断问题**：

1. **准确**：核心事实有直接来源；事实/推断/意见分得开；结论不超出证据边界
2. **观点**：核心判断明确，说明新增价值、适用范围和最强反方，不重复常识充数
3. **有用**：真正回答目标读者问题，给出可执行行动、决策条件或可迁移的理解框架
4. **合声**：符合账号语气但不被模板绑架；个人经历只来自本次用户材料；不挪用范文
5. **好读**：开头迅速进入问题，各节各有任务，论证连贯，标题准确，语言直接无重复

**阻断红线（任一项出现都不能交付）**：编造作者亲历/朋友/采访/对话/场景/身份；核心具体事实无来源或来源不支持；核心论点与证据脱节或把推断写成确定事实；没有给目标读者明确结论/行动/判断方法。

编辑决定：`pass` / `revise`（必须实际改稿并复审，不能只列建议）/ `needs_input`（仅当用户明确要求个人故事而关键材料缺失）。**最多两轮**，第二轮仍未达标不得假装通过：删除不可靠内容、缩小承诺，交付能被证据支持的版本。

## 六、一稿多发（小红书 / 视频号脚本改写）

- 从已批准长文改写，**内容级真改**，不改变主张（与 output-contract 一致）
- 改写后检查编辑质量（五维）与**源稿相似度**（可跑 `wewrite similarity`）；平台版本必须能追溯回同一组主张
- 小红书：图文拆分、口语化、话题标签；视频号：单一记忆点、60-90 秒口播节奏（见 output-contract 验收表）

## 七、任务纪律（与四级闸门一致）

- 每个主题独立目录，不覆盖其他主题
- 初稿 ≠ 成稿：闸门批准前是草稿，批准后才成为表达锚点
- 封存/批准后的原始正文不改写；配图、排版、发布是独立后续动作
- 发布到草稿箱/平台必须用户明确授权；搜索失败时可用分析与经验判断，但**不得把模型记忆包装成已核实事实**
- 来源不足时阻断当前阶段，列出需补充的来源，不用常识或模型记忆填空
