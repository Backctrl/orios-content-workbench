# 选题管道工作流说明（Topic Pipeline）

> 本文档定义 OriOS 内容工作台的选题阶段设计：素材收集 → 选题库 → 主题。任何会话的 Agent
> 在处理「选题」「素材」「候选」相关任务时遵循本说明。对应工作台约定见 `output-contract.md`。

## 一、选题在前，主题在后

```
素材层（异构）                   选题库（统一候选）                   主题层（工作台）
──────────────────────   ──────────────────────────   ──────────────────────────
飞书多维表格 ──lark-base──┐
OrbitOS 知识库 ─orbitos_query┼─→ 候选选题池（多条）──用户选 1+ 条──→ 每条 = 1 个主题
本地/Obsidian ──文件工具──┘   （candidates.yaml）        ↓
                                                  brief.md(选题卡) + claims.yaml + sources/
```

- **选题库是独立于主题的一级概念**：一次素材整理可产出多个候选选题；用户从选题库中挑选，选中的才创建主题。
- 一条选题可以被选多次/拆成多个主题？默认**一条选中 → 一个主题**；若用户明确要求，可在建主题时引用同一条候选（记录候选 id）。
- 未选中的候选**不自动建主题**，保留在选题库中供后续复用。

## 二、候选选题统一格式（candidates.yaml）

选题池持久化在内容根目录的 `_工作台/candidates.yaml`（文件即真相；`_工作台/` 不参与主题扫描）。

```yaml
schemaVersion: 1
updatedAt: 2026-08-28T10:00:00+08:00
items:
  - id: cand-20260828-001
    title: 一个可写的选题标题
    claim: 一句话核心主张（可核验）
    source:
      kind: lark-base | orbitos | file | web
      ref: 素材所在位置（表格记录 id / 知识库页面 / 文件路径 / 链接）
    tags: [标签]
    status: pending | selected | converted
    convertedTopic: 2026-08-ai-workflow   # 转正为主题后回填
```

- `status: pending`：候选；`selected`：用户已选中待转正；`converted`：已建主题（回填主题 id）。
- 候选池结构变化（新候选、状态变更）时更新 `updatedAt`。

## 三、Agent 操作流程

1. **抓素材**：按用户素材来源调用对应能力——
   - 飞书多维表格：`lark-base`（按字段筛：标题/链接/标签/状态）；
   - OrbitOS 知识库：`orbitos_query`（带引用检索）；
   - 本地/Obsidian：文件工具（`glob`/`grep`）扫收集目录。
2. **提取候选**：把素材整理成上述统一格式的候选选题，**写入 `_工作台/candidates.yaml`**（新增或更新），并向用户展示候选清单（标题 + 一句话主张 + 来源）。
3. **用户挑选**：用户说「选 X」「用 1、3」等 → 将对应候选标记 `selected`。
4. **转正建主题**：`creator_create` 建主题 → 把候选的 claim/source 落成 `brief.md`（选题卡）与 `claims.yaml`/`sources/`（主张 + 来源）→ 候选标记 `converted` 并回填主题 id。
5. **进入创作**：按 `output-contract.md` 推进 `brief_sources → approved_article → platform_variants → publish_package`。

## 四、筛选标准（部署时定制，不要预写死）

筛选标准依赖账号定位，**首次部署时通过引导询问**用户账号内容与定位，生成简易模板；长期使用后沉淀优化。
简易模板至少包含：

1. 可核验来源：每个主张能落到一个素材（文件/链接/记录），否则不写入长文。
2. 契合定位：候选符合用户给出的账号定位与目标读者。
3. 单一记忆点：适合 60–90 秒视频口播（对应视频号脚本）。
4. 差异化：与已有主题/内容不重复。

部署引导时询问（记录到工作台设置/技能规则，供后续所有选题使用）：
- 账号定位一句话（做什么内容、给谁看）
- 目标读者画像
- 语气/风格偏好（可交给脚本规则管理）
- 常用选题方向（可选）

## 五、「资料」板块 = 选题卡（方案 B）

- `brief.md` 顶部是**结构化选题卡**：目标读者 / 核心问题 / 边界 / 待验证问题 / 来源（Markdown 列表行，Agent 可解析）。
- 下方为自由正文，用于展开选题思考、事实清单等。
- 工作台「资料」标签页顶部渲染选题卡字段，正文用 Markdown 编辑器（自动保存）。
- 新建主题时 `brief.md` 带选题卡模板；用户可在「资料」页或直接编辑文件填写。

模板：

```markdown
# {主题标题}

> 选题卡：本主题从哪个选题转正而来，服务谁、解决什么问题。

- 目标读者：
- 核心问题：
- 边界：
- 待验证问题：
- 来源：
  - （素材位置或链接）
```
